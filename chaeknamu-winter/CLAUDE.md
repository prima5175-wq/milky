# 책나무 대치 방학특강 신청 앱 — Claude Code 작업 지시서

> 이 파일이 프로젝트의 기준 문서예요. 작업 순서는 12장을 따르고, 각 단계가 끝나면 요약 후 원장 확인을 받고 넘어가요.
> `[미정]` 항목은 임시값으로 진행하되 목록으로 따로 알려요.

## 0. 작업 원칙
- 사용자는 개발자가 아닌 학원 원장이다. 설명은 쉬운 한국어로, 명령어 실행 시 이유를 한 줄로 설명한다.
- 코드 주석, 커밋 메시지, 화면 문구는 모두 한국어.
- 비밀값(Supabase 키, 구글 서비스계정 JSON 등)은 `.env.local`에만 두고 절대 커밋하지 않는다. `.gitignore`부터 확인.
- 배포, DB 삭제·초기화, 실제 학부모 문자 발송 등 되돌릴 수 없는 작업은 먼저 물어본다.
- 학부모 화면에는 정원·남은 자리 숫자가 절대 노출되면 안 된다 (HTML, API 응답, 네트워크 탭 어디에도). (7장)
- 모든 날짜·시간은 Asia/Seoul(KST) 기준. Vercel은 UTC이므로 변환을 명시한다.
- 모바일 우선. 학부모 대부분이 카카오톡 인앱 브라우저로 연다.

## 1. 프로젝트 개요
책나무 강남서초지사 직영 지점(대치·도곡·구룡)의 2027 겨울방학특강 "몰입독서반" 안내·신청 웹앱.
- 이유: 지난 방학 대치점은 접수 30초 만에 마감. 구글폼은 정원 초과·순서 다툼·수작업 정리가 생김. 선착순을 정확히 처리하고 정원이 차면 자동 대기 전환, 환불·보강 규정 동의 기록, "시스템이 다른 학원" 인상.
- 1차 목표(오픈 전 완성): 학부모(안내→신청→완료→조회), 원장(로그인→현황→상태변경→엑셀→설정), 구글시트 자동 기록.
- 2차 목표(방특 중): 출석 체크(강사용), 보강 신청·잔여 횟수, 학부모 조회에 출석·보강 표시.

## 4. 기술 스택
Next.js 15(App Router)+TypeScript+Tailwind / Supabase(Postgres+Auth, Seoul) / Vercel / Google Sheets API(서비스 계정, 복사용) / zod / exceljs 또는 xlsx / (2차 선택) Solapi 문자 — 연동 전 원장 확인.
시트를 원본으로 쓰지 않는 이유: 동시 제출 시 순서가 꼬이고 정원 초과. DB 트랜잭션으로 선착순 확정, 시트는 따라 적기만.

## 6. 데이터베이스 (Supabase / Postgres)
```sql
branches (id uuid pk, slug text unique, name text, sort_order int,
  refund_deadline timestamptz, open_at timestamptz null, close_at timestamptz null,
  contact_url text, notice text, is_active boolean, bundle_price int)
sessions (id uuid pk, branch_id fk, code text, start_date date, end_date date, lesson_count int, price int)
slots (id uuid pk, session_id fk, label text, start_time time, end_time time,
  capacity int null /* 학부모에게 절대 노출 금지 */, sort_order int)
applications (id uuid pk, created_at timestamptz default now(), branch_id fk,
  student_name text, grade int, school text, guardian_phone text /* 숫자만 */,
  enrollment_type text, course text /* 1차/2차/1·2차 */, slot1_id fk null, slot2_id fk null,
  price int, status text /* 확정/대기/취소/환불 */, waitlist_order int null,
  agree_policy boolean, agree_privacy boolean, policy_version text, agreed_at timestamptz,
  memo text, admin_note text, idempotency_key text unique, sheet_synced_at timestamptz null)
admin_users (email text pk, role text /* owner/branch_admin */, branch_id fk null)
application_logs (id, application_id, changed_by, from_status, to_status, note, created_at)
```
- 중복 방지: 같은 지점에서 `학생 이름+보호자 연락처`가 같고 상태가 확정·대기인 신청이 있으면 차단(부분 유니크 인덱스).
- RLS 켠다. 익명은 `applications`, `slots.capacity` 직접 조회 불가. 학부모 화면은 서버 API로만 데이터 수신. 관리자는 `admin_users` 이메일만, branch_admin은 자기 지점만.

## 7. 핵심 로직
### 7-1. 정원 비공개
학부모용 API는 타임마다 `is_full: true/false`만. 정원·신청 수·남은 자리·대기 순번 응답 금지.
표시: 자리 있음 `1부 09:00~10:30` / 마감 `1부 09:00~10:30 · 마감 (대기 신청)`. 대기는 "대기로 접수됐어요"까지만.
개발 후 네트워크 탭에서 숫자 노출 여부를 직접 확인해 보고.

### 7-2. 선착순 접수
`submit_application` Postgres 함수(트랜잭션):
1. 서버 시각이 지점 `open_at` 이후인지 확인(이전이면 거절, 클라이언트 시계 불신).
2. 선택 타임 행을 `SELECT ... FOR UPDATE`로 잠금(1·2차 모두면 둘 다).
3. 각 타임의 '확정' 수를 센다.
4. 모든 타임에 자리가 있으면 확정, 하나라도 마감이면 대기.
5. 대기면 waitlist_order를 해당 타임 기준 다음 번호로 부여.
- [미정] 1·2차 중 한쪽만 마감: 기본 "전체 대기", 대안 "자리 있는 차수는 확정·마감 차수만 대기". 설정으로 전환 가능하게.
6. 중복 신청·`idempotency_key` 중복 확인(같은 키면 처음 결과 반환).
7. 결과(확정/대기, 요약) 반환.
금액은 서버에서 계산, 클라이언트 금액 무시.

### 7-3. 오픈 전 화면
"신청은 12월 ○일(○) 오전 10시에 열려요" 표시, 서버 시각 기준 카운트다운, 오픈 1분 전부터 자동 재확인(새로고침 없이 버튼 열림). 오픈 시각은 지점별 관리자 설정.

### 7-4. 스팸·남용 방지
honeypot 숨김 필드. 같은 IP로는 거의 막지 않는다(학원 와이파이·통신사 망에서 100명 이상이 같은 IP로 동시 접속). IP는 1분 300회 폭주 방지용 한도만 두고, 실제 방어는 같은 연락처 반복 제출(10분 6회)·중복 신청 차단·honeypot. 조회 실패 잠금은 IP가 아니라 '지점+학생 이름' 기준(10분 8회).

### 7-5. 상태 변경(관리자)
- 대기→확정 승격: 취소로 자리 나면 대기 1번부터 승격 버튼. 정원 초과 확정 시 경고+재확인.
- 확정→취소·환불: 환불 마감(대치·도곡 12/27, 구룡 12/20) 이후엔 "규정상 환불 불가 기간입니다" 경고, 사유 입력해야 처리.
- 모든 변경은 `application_logs`에 기록.

## 8. 화면 구성
### 8-1. `/` 랜딩
헤더 "책나무 강남서초지사 · 2027 겨울방학특강" / 제목 "몰입독서반" / 원장 레터(10-1) / 지점 카드 3개(지점명, 1·2차 기간, "안내 보기") / 하단 작게 트리토크 영상 한 줄+링크(큰 썸네일 금지, "방학 독서에 대한 제 생각을 영상으로도 나눴어요", URL [미정]) / 푸터 지점별 문의 링크.
### 8-2. `/[branch]` 지점 안내
일정·수강료 카드(1차/2차/묶음), 설 연휴·주말 안내, 시간표, 지점 운영 메모, 학년별 수업, "신청 전 꼭 확인해 주세요" 박스(10-2), 하단 고정 "신청하기"(오픈 전엔 오픈 시각).
### 8-3. `/[branch]/apply` 신청 폼
한 페이지, 한 손 사용 쉽게.
- 과정 선택(라디오 카드): 1차만/2차만/1·2차 모두 — 기간·회차·금액 표시.
- 타임 선택: 과정에 맞게 1차/2차 칸. 1·2차 모두면 "2차도 같은 시간으로" 기본 체크. 마감 타임 선택 시 10-4 안내.
- 학생 정보: 이름, 학년(1~6, 기본 "현재 학년" [미정]), 학교, 보호자 연락처(010, 하이픈 자동), 재원 구분(신규 / 정규 재원생 / 휴원생(예전에 다닌 적 있음) / 타 지점 수강생), 요청사항(선택 200자).
- 동의(둘 다 체크해야 제출 활성): [필수] 운영 규정(10-2 전문 펼침), [필수] 개인정보(10-3).
- 제출 전 요약(지점, 과정, 타임, 금액, 학생 이름) → "이대로 신청할게요". 제출 중 비활성+"접수 중이에요…".
### 8-4. 완료 화면
확정: "신청이 접수되었어요." + 요약 + "확정 안내 문자는 지점에서 따로 보내드려요. 이 화면을 캡처해 두시면 편해요." / 대기: "대기 신청으로 접수되었어요." + "자리가 나면 신청 순서대로 연락드릴게요." / 입금 안내 [미정].
### 8-5. `/check` 조회
지점+학생 이름+연락처 뒷4자리. 결과는 과정·타임·상태만. 불일치 시 "일치하는 신청이 없어요"만(어느 항목이 틀렸는지 비공개). 같은 IP 연속 실패 시 잠시 차단.
### 8-6. `/admin`

## 11. 2차 기능 (방특 기간 중)
### 11-1. 학생별 출석 체크 (강사용)
- `/admin/attendance`: 날짜·지점·타임을 고르면 해당 타임의 확정 학생 명단이 나온다. 학생마다 **출석 / 지각 / 결석**을 탭 한 번으로 기록(태블릿, 큰 버튼). 잘못 눌렀을 때 바로 고칠 수 있다.
- 수업 시작 30분이 지나도 기록이 없으면 '결석 예정' 표시. 결석 문자는 자동 발송하지 않고 발송 대상 목록만 보여준다(실제 발송은 원장 확인 후).
- 휴원일(설 연휴)과 주말은 날짜 선택에서 제외.
- 대상: 특강 확정 학생만. (정규 재원생 출석은 이 앱에서 다루지 않는다 — 확정)

### 11-2. 수업 기록 (강사가 당일 입력)
학생별·날짜별로 아래를 기록한다.
- **당일 활동**: 자유 입력 (예: 시사독해, 원고지쓰기). 같은 타임 학생에게 한 번에 복사하는 "반 공통 활동" 버튼 제공.
- **선생님 코멘트**: 학생별 자유 입력.
- **활동지 개수**: 숫자.
- **읽은 책**: 책 제목 + 권수. 하루에 여러 권을 추가·삭제할 수 있다.
- 출석 화면에서 학생을 탭하면 같은 화면에서 기록까지 입력(한 화면 완결). 입력은 자동 저장, 나중에 수정 가능.
- 누적 보기: 학생별로 읽은 책 목록·총 권수·활동지 총 개수를 한눈에(원장·강사용). 엑셀 다운로드 포함.
- 수업 기록(활동·코멘트·활동지·책)은 **관리자 화면에서만** 볼 수 있다. 학부모 조회 화면에는 공개하지 않는다. (확정)
- 강사는 **개별 로그인**(역할 `teacher`): 출석·수업 기록 화면만 접근, 자기 지점만. 지점 관리자/원장은 설정·상태변경까지. (확정)

DB(예정): `attendance(application_id, date, slot_id, status, checked_by, checked_at; unique(application_id, date))`, `lesson_records(application_id, date, activity, comment, worksheet_count, recorded_by; unique(application_id, date))`, `lesson_books(record_id, title, volumes)`. 모두 RLS를 켜고 지점 관리자·강사는 자기 지점만 접근.

### 11-2b. 수업 기록 추가 항목 (확정)
- **수업한 강사**: 날짜·타임별로 그날 북토크(수업)를 한 강사를 기록한다.
- **활동지 첨삭 확인**: 그날 한 활동지를 첨삭했는지 체크한다. 나중에라도 **그날 수업한 강사가** 첨삭하고 체크할 수 있고, 첨삭한 강사·시각을 남긴다. 관리자 화면에 "첨삭 안 된 활동지" 목록(날짜·학생·담당 강사)을 보여준다.
- DB(예정): `lesson_records`에 `taught_by`, `worksheet_graded`, `graded_by`, `graded_at` 추가.

### 11-3b. 보강 규칙 (확정)
- 대치점·대치도곡초점은 **1/4(월)부터 보강을 미리 신청**할 수 있다고 안내한다 (`branches.makeup_start_date`, 구룡은 비움 = 차수 시작일부터).
- 보강은 **신청한 차수의 기간 안에서만** 가능: 1차만 신청하면 2차 기간에는 보강 불가(2차만 신청하면 1차 기간 불가). 방학특강 기간이 끝난 뒤 보강은 불가.
- **매주 보강 횟수 확인**: 주 단위로 학생별 보강 사용·잔여 횟수를 모아 보여주고, 학부모에게 안내할 대상 목록을 만든다(문자는 자동 발송하지 않음).

### 8-6b. 관리자 목록 표시 규칙 (확정)
- 학년별 색 구분(1~6학년 6색), 타임(1~5부)별 색, 차수(1차/2차)는 색과 모양을 뚜렷하게 다르게.
- 정렬: 학년 낮은 순. 같은 보호자 연락처(형제·자매)는 학년과 상관없이 묶어서 함께 보여주되, 묶음 안에서는 낮은 학년 순. 묶음의 위치는 가장 낮은 학년 기준. '신청 순' 정렬도 선택 가능(선착순 확인용).
- 이력 표시: 지난 방학에 취소했던 학생 / 지난 여름방학 방특을 들었던 학생 표시(지난 방학 이력은 관리자가 붙여 넣어 등록).
- 상세에서 기존 수강권 메모·수강 종료일을 입력(휴원생·재원생·타 지점 수강생 확인용).

### 11-3. 보강
학부모 조회 화면에서 보강 요청(희망 날짜·시간, 평일 정규시간만, 주말·종료 후 불가). 학생별 3회 한도(지점 설정). 관리자 승인 시 확정. 잔여 횟수 표시.

### 11-4. 학부모 조회 확장
출석 현황(출석 n회/결석 n회), 잔여 보강, 보강 일정, (수업 기록은 공개하지 않음).
