# 책나무 방특 신청 앱 — 원장님 준비 안내서 (처음부터 끝까지)

> 개발을 몰라도 따라 할 수 있게 썼어요. 각 사이트의 화면은 가끔 바뀌어서 버튼 이름이 조금 다를 수 있어요. 그럴 때는 화면을 캡처해서 보내주시면 바로 맞춰서 안내드릴게요.
> **가장 중요한 약속: 비밀번호·키·JSON 파일 내용은 채팅창에 절대 붙여 넣지 마세요.** 4장에 안전하게 전달하는 방법이 있어요.

## 0. 먼저 체험용 주소 만들기 (Supabase 없이, Vercel만으로 15분)

실제 운영 전에 화면을 직접 눌러 보고 싶을 때 쓰는 방법이에요. **Supabase 없이** 임시 DB로 돌아가서 입력한 내용은 저장되지 않고 가끔 초기화돼요. 실제 이름·연락처는 넣지 마세요. 화면 위에 노란 띠로 "체험용 화면이에요"가 표시돼요.

1. `vercel.com` → **Sign Up → Continue with GitHub** (GitHub 계정이 없으면 먼저 `github.com`에서 가입하고, 저장소 `prima5175-wq/milky`를 볼 수 있는 계정으로 로그인).
2. **Add New… → Project** → 저장소 `milky` 옆 **Import**.
3. 설정 화면에서
   - **Root Directory**: **Edit** → `chaeknamu-winter` 선택
   - **Environment Variables**에 두 개 추가: `DEMO_MODE` = `1`, `NEXT_PUBLIC_DEMO_MODE` = `1`
4. **Deploy**. (처음에는 저장소의 기본 브랜치(main)를 배포하려고 해서 실패하거나 빈 화면일 수 있어요. 그때는 다음 5번을 해 주세요.)
5. 지금 코드는 `claude/wonderful-pascal-m2w2d5` 브랜치에 있어요. Vercel 프로젝트 **Settings → Git(또는 Environments → Production → Branch Tracking)**에서 **Production Branch**를 `claude/wonderful-pascal-m2w2d5`로 바꾸고 **Deployments → Redeploy**. 주소(`https://○○○.vercel.app`)가 나오면 완성이에요.
6. 연습용 관리자 로그인: `/admin/login`에서 `owner@example.com`(원장), `daechi@example.com`(지점 관리자), `teacher@example.com`·`teacher2@example.com`(강사)를 입력하면 메일 없이 바로 들어가요.
   - 신청 오픈: 대치점·도곡초점은 열려 있고, 구룡초점은 3일 뒤에 열리게 되어 있어요.
   - 정원: 대치점 1차 1부만 3명이고 나머지는 10명이에요. (마감·대기 화면을 보시려면 대치점 1차 1부로 4번 신청해 보세요.)
7. 이 주소는 **서버가 잠깐 쉬었다 깨어나면 데이터가 초기화**될 수 있어요. 연습·화면 확인용이에요.

> 이 체험용 주소는 Vercel에서 처음 시도하는 설정이라, 배포 중 오류가 나면 배포 로그 화면(빨간 줄)을 캡처해서 보내주세요. 바로 고칠게요.

## 1. Supabase 가입과 프로젝트 만들기

2. **Continue with GitHub**를 누르세요. (GitHub 계정이 이미 있으면 가장 쉬워요. 없으면 이메일로 가입해도 돼요.)
3. 처음이면 조직(Organization)을 만들라고 해요. 이름은 `chaeknamu`처럼 아무거나, 종류는 **Personal**, 요금은 **Free**를 고르세요.
4. **New project**(새 프로젝트) 클릭 후 아래처럼 입력해요.
   - **Name**: `chaeknamu-winter`
   - **Database Password**: 숫자·영문 대소문자만으로 된 **긴 비밀번호**를 만드세요. (예: 영문+숫자 20자 이상. `@ # / ? :` 같은 특수문자는 넣지 마세요. 나중에 연결 주소가 깨져요.) 옆의 **Generate a password** 버튼을 써도 되는데, 특수문자가 섞이면 다시 만들어 주세요. **이 비밀번호를 비밀번호 관리 메모(수첩이나 잠긴 메모)에 꼭 적어 두세요.** 나중에 못 찾아요.
   - **Region**: **Northeast Asia (Seoul)** 선택. (한국에서 가장 빨라요. 꼭 서울!)
   - 요금 플랜: **Free**
5. **Create new project**를 누르고 1~2분 기다리면 완성돼요.

> 무료 플랜 주의: 일주일 정도 아무도 접속하지 않으면 프로젝트가 잠들 수 있어요(Pause). 방학특강 기간처럼 매일 쓰면 괜찮지만, 오픈 직전에 한 번 접속해서 깨어 있는지 확인하세요. 신청이 몰리는 시기에는 월 25달러 안팎의 **Pro 플랜**으로 올리면 더 안정적이에요. (오픈 한 달 전쯤 결정하셔도 늦지 않아요.)

### 1-1. 나중에 필요한 값 3개 찾아 두기
왼쪽 아래 톱니바퀴 **Project Settings**로 들어가요.

- **API** 메뉴 → `Project URL` (https://○○○.supabase.co 모양) → 복사해서 메모에 적기 → 이름: **NEXT_PUBLIC_SUPABASE_URL**
- 같은 화면 `Project API keys`의 **anon / public** 키 → 이름: **NEXT_PUBLIC_SUPABASE_ANON_KEY**
  (이 키는 공개돼도 괜찮은 키예요.)
- **Database** 메뉴 → `Connection string` → 탭에서 **Transaction pooler**(포트 6543)를 고르고 주소를 복사 → 안의 `[YOUR-PASSWORD]` 부분을 위에서 만든 비밀번호로 바꾸기 → 이름: **DATABASE_URL**
  (이 주소는 **비밀**이에요. 남에게 보여주거나 채팅창에 붙여 넣지 마세요.)

> 절대 쓰지 말아야 할 키: `service_role` 키는 이 앱에서 쓰지 않아요. 보이더라도 복사하지 마세요.

## 2. 테이블 만들기 (SQL 붙여 넣기)

1. Supabase 왼쪽 메뉴 **SQL Editor** 클릭 → **New query**.
2. GitHub 저장소(`prima5175-wq/milky`)의 `chaeknamu-winter/supabase/migrations/0001_init.sql` 파일을 열어 **전체 복사** → SQL Editor에 붙여 넣기 → 오른쪽 아래 **Run**.
   - 맨 아래에 `Success. No rows returned`가 나오면 성공이에요.
3. 새 query를 하나 더 열어 `chaeknamu-winter/supabase/seed.sql` 전체를 같은 방식으로 **Run**. (지점 3곳·차수·타임·학년별 수업·보강 시작일이 들어가요.)
   - ⚠ `dev-seed.sql`은 **절대 실행하지 마세요.** 연습용 가짜 계정이 들어가는 파일이에요.
4. 왼쪽 **Table Editor**에서 `branches`, `sessions`, `slots` 등이 보이면 성공이에요. `branches`에 3행이 있어야 해요.
5. 관리자 등록: SQL Editor에서 아래를 **이메일만 바꿔서** Run.
   ```sql
   insert into admin_users (email, role, branch_id) values
    ('원장님이메일@gmail.com', 'owner', null);
   -- 지점 관리자 예시 (대치점)
   insert into admin_users (email, role, branch_id)
    select '대치점관리자@gmail.com', 'branch_admin', id from branches where slug = 'daechi';
   -- 강사 예시 (대치점) — 출석 기능을 만든 뒤 사용
   insert into admin_users (email, role, branch_id)
    select '강사@gmail.com', 'teacher', id from branches where slug = 'daechi';
   ```
   이 목록에 없는 이메일은 로그인 자체가 안 돼요.

> 이 단계에서 에러가 나면 **빨간 에러 문장을 그대로 캡처**해서 보내주세요.

## 3. Vercel 가입과 배포 (학부모가 여는 주소 만들기)

### 3-1. 가입
1. `vercel.com` → **Sign Up** → **Continue with GitHub** (BookSpec을 올리던 계정이 있으면 그 계정으로).
2. 요금제는 **Hobby(무료)**로 시작하세요.
   - 참고: Hobby는 "개인·비상업" 용도라고 약관에 적혀 있어요. 학원 사업용이니 **오픈 전에 Pro 플랜(월 약 20달러)으로 올리는 걸 권해요.** 약관을 지키는 방법이고, 접속이 몰려도 더 안정적이에요.

### 3-2. 프로젝트 가져오기
1. **Add New… → Project** → GitHub 저장소 `milky`가 보이면 **Import**. (안 보이면 **Adjust GitHub App Permissions**에서 이 저장소를 허용.)
2. 설정 화면에서 꼭 바꿀 것 두 가지:
   - **Root Directory**: **Edit**를 눌러 `chaeknamu-winter` 선택. (이걸 안 하면 다른 폴더를 배포하려고 해서 실패해요.)
   - **Framework Preset**: `Next.js` (자동으로 잡혀요).
3. **Environment Variables**(환경 변수)에 아래를 하나씩 입력해요. 이름은 **대문자 그대로** 정확히 써 주세요.

   | 이름 | 값 |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | 1-1에서 복사한 Project URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 1-1의 anon 키 |
   | `DATABASE_URL` | 1-1의 Transaction pooler 주소(비밀번호 넣은 것) |
   | `NEXT_PUBLIC_SITE_URL` | 배포 후 나오는 주소 (처음에는 임시로 `https://example.com` 넣고, 배포 뒤에 진짜 주소로 고쳐요) |
4. **Deploy** 클릭 → 1~3분 후 폭죽 화면과 함께 주소(`https://○○○.vercel.app`)가 나와요.
5. 그 주소를 복사해서 **Settings → Environment Variables**의 `NEXT_PUBLIC_SITE_URL` 값을 진짜 주소로 고치고, **Deployments → 맨 위 배포 → ⋯ → Redeploy**를 눌러요.

### 3-3. 어떤 코드가 배포되나요? (중요)
지금까지 만든 코드는 GitHub의 `claude/wonderful-pascal-m2w2d5` 브랜치에 있어요. Vercel은 기본적으로 `main` 브랜치를 "진짜 주소"로 배포해요.
- **연습 단계**: 이 브랜치만으로도 Vercel이 따로 미리보기 주소를 만들어 줘요(Preview). 이걸로 리허설해도 돼요.
- **진짜 오픈 전**: 제가 `main`으로 합치는 요청(PR)을 만들어 드릴게요. 원장님이 "합쳐도 돼요"라고 하시면 진행해요. (합치기 전에는 반드시 확인받을게요.)

### 3-4. 도메인(선택)
`winter.○○○.kr` 같은 전용 주소를 쓰려면 Vercel **Settings → Domains**에 입력하고, 도메인을 산 곳(가비아·후이즈 등)에서 Vercel이 알려주는 **CNAME 값**을 추가하면 돼요. 막히면 도메인 관리 화면을 캡처해서 보내주세요.

## 4. 로그인 메일 설정 (관리자·강사)

관리자는 비밀번호 대신 **이메일로 온 링크를 눌러** 로그인해요.

1. Supabase → **Authentication → URL Configuration**
   - **Site URL**: 3-2의 진짜 주소 (`https://○○○.vercel.app`)
   - **Redirect URLs**: `https://○○○.vercel.app/admin/callback` 추가 (**Add URL**). 전용 도메인을 쓰면 그 주소로도 한 줄 더 추가.
2. **메일 발송 한도 주의 (중요)**: Supabase 기본 메일 발송은 **시간당 몇 통으로 제한**되고, 프로젝트 팀원에게만 보내지는 경우가 있어요. 직원(강사) 여러 명이 로그인하려면 **자체 메일 서버(SMTP) 연결**을 권해요.
   - 가장 쉬운 방법: **Resend**(resend.com, 무료 월 3,000통). 가입 → **API Keys**에서 키 만들기 → Supabase **Authentication → Emails → SMTP Settings**에 Resend가 알려주는 호스트·포트·사용자·비밀번호 입력.
   - 도메인이 없으면: 구글 계정의 **앱 비밀번호**(2단계 인증 켜고 발급)로 Gmail SMTP(`smtp.gmail.com`, 포트 587)를 쓰는 방법도 있어요.
   - 어려우면 이 부분은 화면을 캡처해서 보내주세요. 같이 맞춰 드릴게요.
3. 확인: `https://○○○.vercel.app/admin/login`에서 2번에 등록한 원장 이메일을 입력 → 메일 확인 → 링크 클릭 → 관리자 화면이 열리면 성공!
   - ⚠ 이 이메일 링크 로그인은 **아직 실제 Supabase에서 시험해 보지 못한 부분**이에요. 첫 연결 때 제가 가장 먼저 같이 확인할게요.

- **환불·변경 마감**: 대치·도곡 12/27(일) 23:59, 구룡 12/20(일) 23:59 (구룡은 확인 필요)
- **타임별 정원**: 차수별·타임별 숫자 입력 (비우면 제한 없음). 시드값은 모두 10이에요. **오픈 전에 꼭 실제 정원으로 바꾸세요.**

## 6. 구글 서비스 계정 + 구글시트 (신청이 시트에 자동으로 쌓이게)

신청 내용이 구글시트에 **복사**돼서 쌓이는 기능이에요(보기용). 못 만들어도 앱은 정상 동작하고, 엑셀 다운로드로 대신할 수 있어요. 아래는 이 기능을 켜기 위한 준비예요.

### 6-1. 구글 클라우드 프로젝트 만들기
1. `console.cloud.google.com` 접속 (원장님 구글 계정으로 로그인) → 약관 동의.
2. 맨 위 프로젝트 선택 상자 → **새 프로젝트** → 이름 `chaeknamu-winter` → **만들기**. (결제 정보는 필요 없어요. 이 기능은 무료 한도 안에서 충분해요.)

### 6-2. 시트 사용 허용
1. 왼쪽 메뉴 **API 및 서비스 → 라이브러리**.
2. 검색창에 `Google Sheets API` → 클릭 → **사용**.

### 6-3. 서비스 계정 만들기
1. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → 서비스 계정**.
2. 이름 `sheet-mirror` → **만들고 계속하기** → 역할은 건너뛰고 **완료**.
3. 목록에 생긴 서비스 계정을 클릭 → 위쪽 **이메일**(`sheet-mirror@○○○.iam.gserviceaccount.com`)을 복사해 메모. 이게 **GOOGLE_SERVICE_ACCOUNT_EMAIL** 이에요. (이건 채팅에 알려주셔도 괜찮아요.)
4. **키** 탭 → **키 추가 → 새 키 만들기 → JSON → 만들기** → 컴퓨터에 `.json` 파일이 내려받아져요.
   - ⚠ 이 파일은 **비밀번호와 같아요.** 채팅창에 내용을 붙여 넣거나 이메일로 보내지 마세요. 파일 안의 `private_key` 값이 **GOOGLE_PRIVATE_KEY** 예요. 4장 방식으로만 전달해요.
   - 파일을 이 저장소(GitHub)에 올리면 안 돼요. (이미 자동으로 막아 두었지만, 직접 올리지도 마세요.)

### 6-4. 구글시트 만들고 공유하기
1. `sheets.google.com` → 빈 스프레드시트 만들기 → 이름 `2027 겨울방특 신청 현황`.
2. 오른쪽 위 **공유** → 6-3의 서비스 계정 이메일을 입력 → 권한 **편집자** → **보내기** (알림 메일 체크 해제해도 돼요).
3. 시트 주소창 `https://docs.google.com/spreadsheets/d/`**여기가_시트_ID**`/edit` — 굵게 표시한 부분이 **GOOGLE_SHEET_ID** 예요. (채팅에 알려주셔도 괜찮아요.)
4. 탭(시트) 이름은 제가 자동으로 만들어요: `대치점`, `도곡초점`, `구룡초점`, `전체`.
5. 시트는 **보기용**이에요. 시트에서 고친 내용은 앱에 반영되지 않아요. 수정은 항상 관리자 화면에서 해요.

### 6-5. Vercel에 값 넣기
Vercel **Settings → Environment Variables**에 3개 추가:
| 이름 | 값 |
|---|---|
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | 6-3의 서비스 계정 이메일 |
| `GOOGLE_SHEET_ID` | 6-4의 시트 ID |
| `GOOGLE_PRIVATE_KEY` | JSON 파일의 `private_key` 값 전체 (`-----BEGIN PRIVATE KEY-----`부터 `-----END PRIVATE KEY-----\n`까지, 따옴표 제외) |

넣은 뒤 **Redeploy** 해주세요.

## 7. 제가 직접 연결 상태를 확인하려면 (선택)

실제 Supabase에 대고 제가 정원·동시 접수를 다시 시험하려면, 이 작업 환경이 비밀값을 읽을 수 있어야 해요.

1. 화면 위쪽 제목줄의 **클라우드 환경 메뉴 → Edit**를 열어요.
2. **환경 변수**(또는 Network secrets / API credentials)에 아래를 추가해요. **값은 여기 입력칸에만** 넣고 채팅에는 붙이지 마세요.
   - `DATABASE_URL` (1-1의 Transaction pooler 주소)
3. **Network access**가 제한되어 있다면 Supabase 주소(`○○○.supabase.co`, `aws-○-ap-northeast-2.pooler.supabase.com`)를 **Allowed domains**에 추가해야 접속돼요.
4. 새 세션을 열면 적용돼요. 그 뒤 "연결 확인해줘"라고 말씀해 주세요.

이 단계를 하지 않아도 앱은 문제없이 배포·운영돼요. 다만 **오픈 전에 직원분들과 하는 리허설(8장)**이 실제 환경에서의 최종 확인 역할을 해요.

## 8. 리허설 (오픈 전, 직원 3~5명)

1. 신청 시작 시각을 **지금 이후 가까운 시각**(예: 10분 뒤)으로 설정해 두세요. (오픈 전 카운트다운도 직접 보실 수 있어요.)
2. 직원분들이 각자 **휴대폰(카카오톡 인앱 브라우저 포함)**으로 신청 링크를 열어요.
3. 오픈 시각에 **동시에** 가짜 이름(예: `테스트1`)으로 신청해요. 정원이 작은 타임(예: 정원 2)을 일부러 골라서, 확정과 대기가 나뉘는지 보세요.
4. 학부모 화면에 정원·남은 자리 **숫자가 보이지 않는지** 확인해요.
5. 관리자 화면(현황·신청 목록)에서 확정/대기 수, 대기 순번, 형제 묶음, 색 구분이 맞는지 확인해요.
6. **신청 조회**(이름 + 연락처 뒷 4자리)가 되는지 확인해요.
7. 구글시트를 연결했다면 시트에 행이 생겼는지 확인해요.
8. 끝나면 **테스트 데이터 삭제** — 삭제 전에 제가 원장님께 먼저 확인받고 지울게요. 정원·오픈 시각을 실제 값으로 되돌리는 것도 잊지 마세요.

## 9. 오픈 전날 점검표

- [ ] 정원 숫자를 **실제 값**으로 입력했다
- [ ] 지점별 **신청 시작 시각**이 맞다 (한국 시간, 오전/오후 확인)
- [ ] 환불 마감일이 맞다 (구룡 12/20 확인)
- [ ] 안내 문구·학년별 수업·문의 링크를 최신으로 고쳤다
- [ ] 개인정보 보유 기간 문구를 확정했다
- [ ] 관리자·지점 관리자 이메일이 `admin_users`에 등록되어 있고 로그인이 된다
- [ ] 테스트 신청 데이터를 모두 지웠다 (확인 후)
- [ ] Supabase 프로젝트가 잠들어 있지 않다 (접속해서 확인)
- [ ] 리틀리 등 링크 위치에 **진짜 주소**를 걸었다
- [ ] 휴대폰으로 `신청 링크`를 직접 열어 본다 (카카오톡 안에서도)

## 자주 막히는 곳

| 증상 | 이렇게 해보세요 |
|---|---|
| Supabase에서 SQL을 실행했는데 빨간 에러 | 에러 문장 전체를 캡처해 보내주세요. 같은 SQL을 두 번 실행하면 "already exists" 에러가 나는 건 정상이에요. |
| Vercel 배포가 빨간색으로 실패 | **Root Directory**가 `chaeknamu-winter`인지, 환경 변수 이름 오타가 없는지 확인. 그래도 안 되면 배포 로그 화면을 캡처해 주세요. |
| 사이트는 열리는데 "접수 중 문제가 생겼어요" | `DATABASE_URL`이 비어 있거나 비밀번호가 틀렸을 때 나와요. 비밀번호에 특수문자가 있다면 영문·숫자로 바꾸고 주소를 다시 만드세요. |
| 로그인 메일이 안 와요 | 스팸함 확인 → 4장의 SMTP 설정 → 이메일이 `admin_users`에 있는지 확인. |
| 구글시트에 안 쌓여요 | 서비스 계정 이메일이 시트에 **편집자**로 공유됐는지, Sheets API가 **사용** 상태인지 확인. 앱은 시트가 실패해도 신청 자체는 정상 접수돼요. |
